# 产品简报、文案与质检

## 产品简报字段

先整理并区分两类信息：

- 已确认事实：型号、核心卖点、适用场景、关键参数、用户痛点、证明材料、限制条件、价格/优惠和行动引导。
- 待确认信息：任何推断、缺失参数、功效、库存、对比结论、发布时间和禁用词。

资料不足时列缺项，不用猜测补齐。用户已提供资料时直接写成稿，不设置产品简报确认停顿；只有缺少关键事实导致无法真实表达时才暂停。

## 文案输出

保存 `01_文案\发布稿.md`，包含文案类型、标题、正文、话题、封面建议、素材发布顺序和事实来源备注。先按 [copy-types.md](copy-types.md) 选定类型，再建立编辑 brief，最后成稿。任务清单必须记录 `content_goal`、`narrative_mode`、`evidence_level`、`distribution_role` 和 `copy.version`。

### 文案类型

创建内容且用户未指定时，默认 `seeding` 种草分享。用户点名或说出别名时改用对应类型；“种草加点品宣 / 不要太正式”用 `hybrid`；“按方案写 / 不要默认种草”用 `official` 或 `launch`。类型写入成稿首行和任务清单 `copy.copy_type`。

文案风格管语气，默认跟类型走：种草用口语种草，品宣/新品/活动用克制品宣，综合稿用轻松综合，教程/清单用步骤说明，问答/测评用问答克制。用户另指定时，类型仍管结构，风格只管语气。风格写入 `copy.copy_style`。创建内容前确认类型和风格；这不是产品简报确认，也不是成稿确认。

分类型结构、标题、话题和语气以 `copy-types.md` 为准，不要把种草规格套到品宣稿上。

### 编辑阶段门

按 `brief待补` → `draft初稿` → `review质检` → `approved已审` → `scheduled待发` → `published已发` 推进。brief 至少写明受众、场景、核心命题、一级卖点、事实编号、证据等级、禁用表达、CTA、素材需求和成功指标；任一事实缺口都必须回到 `brief待补` 或 `待补资料`。

### 默认种草规格

仅 `seeding` 和 `hybrid` 使用：先写具体生活痛点，再带出产品；正文只放 1-3 个与场景直接相关的参数，其余放“参数小抄”。可用第一人称偏好，但不得虚构亲测、使用时长、回购或效果。标题 5 个（每个不超过 20 字、含 emoji 和第二人称/人群词），正文每段不超过 3 行，话题 8-15 个。

`official` / `launch` / `faq` / `campaign` 不用种草人设，按方案顺序或问答结构写。

所有类型都要避免无法证明的“第一、最好、绝对有效、零风险”，只用可追溯事实。内部溯源措辞不得进入对外字段。

不要求用户在中途查看或修改文案。完成素材检查后，在最后发布预览一次性展示类型、风格、标题、正文、话题、可见性和素材顺序；素材与文案不一致时，回到文案或素材检查门，不强行发布。

## 发布前质检

逐项确认：

- 型号、参数和产品名称没有串错
- 每个素材都能支撑对应文案句子
- 没有内网路径、账号信息或未公开信息进入对外内容
- 素材顺序、封面和标题符合叙事
- 本机文件能正常打开，路径不在 C 盘
- 用户已看到预览摘要并明确确认发布
- 文案类型和风格已选定并写入清单，结构符合类型，语气符合风格
- 内容目的、叙事方式、证据等级和分发角色已写入清单，且与主类型一致
- brief、成稿和素材之间可逐句回链；版本号递增且历史版本未被覆盖
- 种草/综合稿有具体场景开头；品宣/新品稿未套种草人设
- 无虚构体验，参数不过载

质检未通过时状态保持为 `待素材检查` 或 `待确认发布`，不要调用发布接口。
