# 小红书文案类型规格 v1.2

适用：`xiaohongshu-publishing` 的文案门。本文件只规定文案类型、语气、结构和验收；不改变登录、共享盘只读、事实追溯和发布确认。

检查日期：2026-09-11

公开参考（只用于分类，不作为产品参数来源）：

- 小红书创作者学院常见笔记形态：图文、视频、直播；内容上常见种草、测评、教程、合集
- 品牌侧常见：新品发布、卖点品宣、活动促销、官方答疑
- 本 skill 实际任务还需要：种草与品宣的综合稿

## 1. 两个不要混的分类

| 字段 | 管什么 | 例子 |
|---|---|---|
| 储存分类 | 任务库归档 | 新品宣发 / 日常种草 / 活动促销 / 其他 |
| 文案类型 | 这一篇怎么写 | `seeding` 种草分享 / `official` 官方品宣 / `hybrid` 种草品宣综合 |

同一条“新品宣发”任务，可以写成种草、品宣或综合稿。不得用储存分类代替文案类型。

## 2. 选择规则 MUST

1. 用户明确点名类型、或说出可映射别名时，使用该类型。
2. 用户同时要“种草 + 品宣 / 不要这么正式 / 带点种草带点品宣”时，使用 `hybrid`。
3. 用户只给上市方案、卖点策划、海报口号，并说按方案写、不要默认种草时，使用 `official` 或 `launch`。
4. 创建内容且用户未指定时，默认 `seeding`。
5. 发布或定时已有任务时，沿用保存包里的 `copy.copy_type`，不重新猜。
6. 选中类型后写入 `任务清单.json` 的 `copy.copy_type` 和 `copy.copy_type_name`；成稿开头用一行注明类型。

不得因为模板没填就改类型。找不到匹配时先按默认种草，并在备注里写“未指定，已用默认种草分享”。

## 2.1 文案风格

风格管语气，类型管结构。创建内容前，类型和风格属于需要用户确认的字段；用户已经说清的直接用，没说的按默认。不要再拿成稿确认一次，也不要用储存分类代替风格。

| ID | 名称 | 默认对应类型 | 语气 |
|---|---|---|---|
| `spoken_seeding` | 口语种草 | `seeding` | 聊天、场景、可用“姐妹/宝子” |
| `restrained_official` | 克制品宣 | `official` / `launch` / `campaign` | 清楚克制，不走人设 |
| `light_hybrid` | 轻松综合 | `hybrid` | 口语讲卖点，口号最多 1 个 |
| `stepwise` | 步骤说明 | `tutorial` / `listicle` | 短句、按点说完 |
| `qna_restrained` | 问答克制 | `faq` / `review` | 先答顾虑，不编体验 |

规则：

1. 只指定类型：风格用该类型默认值。
2. 只指定风格：类型用上表默认对应的第一个类型。
3. 两个都指定：类型决定结构，风格决定语气；冲突时仍按这一条，并在备注写明。
4. 发布或定时已有任务：沿用 `copy.copy_style`，不重新猜。
5. 写入 `任务清单.json` 的 `copy.copy_style` 和 `copy.copy_style_name`。

## 3. 类型总表

| ID | 名称 | 用户可能怎么说 | 默认引擎 | 适用 |
|---|---|---|---|---|
| `seeding` | 种草分享 | 种草、好物分享、日常笔记 | `zhongcao` | 生活场景带出产品 |
| `official` | 官方品宣 | 品宣、官方稿、卖点策划、按方案写 | 本 skill 品宣规格 | 品牌口径、卖点顺序 |
| `launch` | 新品发布 | 首发、上市、新品 | 本 skill 品宣规格 | 第一轮认知：差异点 + 怎么用 |
| `hybrid` | 种草品宣综合 | 种草加点品宣、不要太正式 | `zhongcao` + 方案卖点 | 口语讲方案里的核心卖点 |
| `review` | 测评对比 | 测评、对比、值不值得 | `zhongcao` | 只写已核实差异，不编评测过程 |
| `tutorial` | 教程指南 | 怎么用、开箱、步骤 | `zhongcao` | 按步骤说明，不编使用时长 |
| `listicle` | 清单盘点 | 几点、合集、场景清单 | `zhongcao` | 3–5 个可追溯卖点 |
| `faq` | 问答避坑 | 避坑、FAQ、常见问题 | 本 skill 品宣规格 | 只答资料里有的限制和边界 |
| `campaign` | 活动促销 | 活动、优惠、大促 | 本 skill 品宣规格 | 价格和规则必须可追溯 |

## 3.1 大厂编辑分类法（四层标签）

文案类型是主路由；以下三层是必填辅助标签，不能替代 `copy_type`：

| 层级 | 字段 | 可选值 | 作用 |
|---|---|---|---|
| 目的 | `content_goal` | `awareness`认知 / `consideration`考虑 / `conversion`转化 / `retention`留存 / `interaction`互动 | 决定首屏承诺和行动引导 |
| 叙事 | `narrative_mode` | 场景痛点 / 观点解释 / 证据测评 / 步骤教程 / 清单收藏 / 问答消疑 / 节点促销 / 用户共创 | 决定正文骨架与素材顺序 |
| 证据 | `evidence_level` | L0待补 / L1官方资料 / L2可见参数或演示 / L3第三方或用户授权实测 | 决定能否使用体验、对比和效果词 |
| 分发 | `distribution_role` | `brand_owned`品牌号 / `creator_collab`达人合作 / `ugc_prompt`用户共创 / `search_evergreen`搜索长效 | 决定语气、CTA 与话题策略 |

最低路由规则：`official` 默认 `awareness + brand_owned`；`seeding` 默认 `consideration + creator_collab`；`tutorial/listicle/faq` 默认 `search_evergreen`；`campaign` 默认 `conversion`。用户明确要求优先，未提供时才使用默认。一次交付只能有一个主类型和一个主目标；需要不同目标时另开版本。

## 3.2 编辑交付契约

每个版本先产出编辑 brief，再写成稿：受众/场景、核心命题、一级卖点、证据等级、禁用表达、CTA、素材需求、成功指标。成稿必须能逐句回链到 brief 的事实编号；缺证据的句子降级为“待确认”，不得用修辞掩盖。

版本状态固定为：`brief待补` → `draft初稿` → `review质检` → `approved已审` → `scheduled待发` → `published已发`。任何事实、类型、目标或证据等级变化都要递增 `copy.version` 并保留上一版，不覆盖历史。

## 3.3 大厂质量门（发布前 MUST）

1. **策略门**：主类型、内容目的、受众和 CTA 一致；首屏 3 秒内能读懂主题。
2. **事实门**：每个参数、价格、功效和对比都有来源编号；L0/L1 不得写亲测效果。
3. **表达门**：标题不过度承诺；一段一意；品牌稿不装个人体验，种草稿不写成说明书。
4. **平台门**：广告/合作披露按平台要求处理；不使用新闻播报式广告、虚假稀缺、绝对化和无法证明的权威背书。
5. **资产门**：首图承担主题，图片顺序与正文段落一一对应；素材来源、版权和授权状态可追溯。
6. **复盘门**：保存发布版本、发布时间、曝光/互动/收藏/点击等可得指标；复盘只改下一版，不回写已发布正文。

一次任务只选一个主类型。需要第二篇不同类型时，另开文案版本，不把两种结构揉进同一段主稿，除非主类型就是 `hybrid`。

## 4. 公共 MUST

所有类型都要遵守：

- 事实、参数、功效、价格只能来自已核实资料；缺口标待确认，不猜。
- 不虚构亲测、回购、使用时长、订单和效果。
- 不写“第一、最好、闭眼冲、绝对有效、零风险、无菌、全屋、0 维护”。
- 对外文案不出现共享盘路径、素材标注、内部审计话术。
- 保存 `01_文案/发布稿.md` 或任务包根目录约定的文案文件，至少包含：类型、标题、正文、话题、配图建议、事实边界。
- 冲突参数（如两份资料口径不一致）不进入对外卖点，只写在内部边界。

## 5. 分类型规格

### `seeding` 种草分享

- 目标：让读者觉得“这和我的生活有关”。
- 语气：像和熟人聊天。可用“姐妹/宝子/真的/刚好/不占地方”。每 2–3 句一个 emoji，不连续堆感叹号。
- 结构 MUST：开头 2–3 行写具体生活痛点（空调房干、通勤、排队、包太小），再引出产品；中段 3–4 个场景化优点；参数放“参数小抄”。
- 标题 MUST：5 个备选，每个不超过 20 字，含 1 个 emoji，以及第二人称或人群词。
- 话题 MUST：8–15 个，按热门、品类、人群、场景、长尾混合。
- 正文每段不超过 3 行；正文里只留 1–3 个和场景直接相关的参数。
- 可用第一人称偏好（“我会更在意轻不轻”），但不能写成已经用过、已经回购。

### `official` 官方品宣

- 目标：把品牌要建立的认知讲清楚，不是闺蜜安利。
- 语气：清楚、克制、可读。不用“姐妹们/宝子们/绝绝子”，也不用公文腔“现将产品介绍如下”。
- 结构 MUST：海报短句 → 核心差异（1 段）→ 按方案顺序的卖点段落 → 场景 → 参数。
- 标题：3–5 个，不超过 20 字；突出差异点或产品名，emoji 可选，不强行第二人称。
- 话题：6–12 个，以品牌、型号、品类、卖点为主，少用纯热门灌流词。
- 卖点顺序跟用户方案走；方案没有的不补。
- 品牌背书、评价晒单、奖项没有资料就标待补，不编。

### `launch` 新品发布

- 目标：几秒内看懂“和旧方案有什么不同，怎么开始用”。
- 语气：接近品宣，可稍轻，但不走种草人设。
- 结构 MUST：一句话差异 → 怎么用（插上/打开/场景）→ 2–3 个首轮卖点 → 适用边界 → 参数。
- 标题：3–5 个，含产品名或“新品/首发/不用棉芯”这类差异词，不超过 20 字。
- 首轮卖点只取方案里的一级卖点，不把三级细节堆进正文。

### `hybrid` 种草品宣综合

- 目标：读起来像分享，但卖点来自官方方案。
- 语气：口语，可有“姐妹/你”；品宣口号只保留 1 个（如“活水小雾棒”），不整段照搬方案。
- 结构 MUST：生活痛点开头 → 用方案核心差异接住 → 3–4 个场景化卖点 → 一句选择偏好 → 参数小抄。
- 标题 MUST：5 个，规则同种草。
- 话题 MUST：8–15 个，热门词和型号/卖点词都要有。
- 禁止把方案对比表、路径图、注释、待补测试报告写进正文。

### `review` 测评对比

- 目标：帮助判断“适不适合”，不是制造赢面。
- 语气：明白、克制。
- 结构 MUST：要解决的问题 → 可核实差异（功能/结构/维护）→ 适合谁 / 不适合谁 → 参数。
- 没有实测数据时，只能写资料对比，不能写“我测了两周”“出雾明显更大”。
- 不点名攻击竞品，除非用户明确要求且资料允许；默认写“常见棉芯款 / 需要固定水箱的款”。

### `tutorial` 教程指南

- 目标：按完就能用。
- 语气：短句、步骤清楚。
- 结构 MUST：适用条件 → 步骤 1…n → 常见误判（灯、档位、缺水）→ 维护边界。
- 步骤必须来自资料（按键顺序、灯光、容器口径、充电）。缺步骤就标待补，不编。

### `listicle` 清单盘点

- 目标：一条笔记讲清 3–5 个点，方便收藏。
- 结构 MUST：一句总判断 → 3–5 个带小标题的点 → 一句适用边界。
- 每个点一句话卖点 + 一句限制或场景，不展开成长文。

### `faq` 问答避坑

- 目标：先回答顾虑。
- 结构 MUST：3–6 个问答。问句用用户会问的话，答句只用已核实事实。
- 适合：会不会湿桌、要不要换棉芯、什么瓶子能用、算不算静音、能不能当全屋加湿。
- 资料冲突的问题（如边充边用）回答“以说明书为准 / 暂不宣传”，不选边编造。

### `campaign` 活动促销

- 目标：讲清活动规则，再带产品差异。
- 结构 MUST：活动对象和时间 → 规则 → 产品一句差异 → 购买边界。
- 没有价格、券、库存就不得写“低价、秒光、仅限今天”。

## 6. 标题、正文、话题对照

| 类型 | 标题数量 | 标题必须有 emoji | 必须有人群/第二人称 | 话题数量 | 参数位置 |
|---|---|---|---|---|---|
| seeding / hybrid | 5 | 是 | 是 | 8–15 | 正文 1–3 个，其余小抄 |
| official / launch / faq / campaign | 3–5 | 否 | 否 | 6–12 | 可集中在参数区 |
| review / tutorial / listicle | 3–5 | 建议 | 建议 | 8–12 | 小抄或步骤旁 |

## 7. 任务清单字段

```json
{
  "copy": {
    "copy_type": "hybrid",
    "copy_type_name": "种草品宣综合",
    "copy_style": "light_hybrid",
    "copy_style_name": "轻松综合",
    "content_goal": "consideration",
    "narrative_mode": "场景痛点",
    "evidence_level": "L1",
    "distribution_role": "creator_collab",
    "version": 1,
    "engine": "zhongcao+用户方案",
    "status": "已整理"
  }
}
```

`copy_type` 用本文件 ID。改类型等于改文案版本，需更新 `copy.version` 和 `updated_at`。

`copy_style` 用本文件风格 ID。改风格也要更新 `copy.version`。

## 8. 验收

1. 主类型唯一，且和用户当次要求一致。
2. 结构、语气、标题和话题符合该类型规格。
3. 公共 MUST 全部满足。
4. `hybrid` 必须同时有生活场景开头和至少 1 个方案差异点。
5. `official` / `launch` 不得套种草人设；`seeding` 不得写成说明书。
6. 未通过时状态保持 `待补资料` 或 `待确认发布`，不调用发布接口。
